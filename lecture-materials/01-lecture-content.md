## 1. 바이브 코딩(Vibe Coding)이란?

### 1.1 정의
바이브 코딩은 코드를 직접 작성하지 않고, 원하는 결과물을 **자연어로 설명**하면 AI가 실제로 동작하는
코드를 만들어주는 개발 방식이다. 사용자는 결과물을 보고 "이 부분을 이렇게 바꿔줘"처럼 대화로
피드백하며 완성도를 높여간다.

핵심은 프로그래밍 문법 지식이 아니라 **원하는 것을 구체적으로 설명하는 능력**이다.

### 1.2 전통적 코딩과의 차이

| | 전통적 코딩 | 바이브 코딩 |
|---|---|---|
| 필요 지식 | 프로그래밍 언어 문법 | 요구사항을 구체적으로 설명하는 능력 |
| 작업 방식 | 직접 코드 작성 → 실행 → 디버깅 | 자연어 요청 → AI가 코드 생성 → 결과 확인 → 대화로 수정 |
| 진입장벽 | 높음 (수개월~수년 학습) | 낮음 (당일 실습 가능) |
| 적합한 대상 | 개발자 | 아이디어와 도메인 지식이 있는 누구나 (교사 포함) |

### 1.3 왜 지금 과학교사에게 유용한가
- 학교 현장에는 "딱 맞는 도구"가 없는 경우가 많다 — 기존 상용 앱은 필요 이상으로 복잡하거나,
  필요한 기능이 빠져 있다.
- 외주 개발은 비용·시간 부담이 크고, 만든 뒤 수정도 어렵다.
- 바이브 코딩은 교사가 **직접, 그 자리에서, 무료로** 필요한 도구를 만들고 즉시 수정할 수 있게 한다.
- 코딩을 몰라도 되므로, "이런 게 있으면 좋겠다"는 아이디어만 있으면 시작할 수 있다.

## 2. 오늘 사용하는 도구와 개념

### 2.1 제미나이(Gemini) + Canvas 모드
- gemini.google.com에서 구글 계정(학교 계정 포함)으로 바로 사용 가능한 무료 AI 챗봇.
- **Canvas(캔버스) 모드**: 입력창 근처의 "도구(+)" 버튼으로 켤 수 있으며, 결과가 채팅창이 아니라
  별도 화면에 코드/미리보기 형태로 나타난다. 코드를 만들고 다듬을 때 특히 편리하다.
- 응답 모드: 간단한 요청은 **빠른 모드(Flash)**, 복잡한 로직은 **사고 모드(Thinking)**가 유리하다.
- 프롬프트 마지막에 **"html로 만들어줘"**를 붙이면, 브라우저에서 바로 열어볼 수 있는 완성된 단일
  HTML 파일로 결과가 나온다.
- 완성 후 화면 위쪽 **공유 버튼**으로 링크를 만들면, 다른 사람도 그 결과물을 바로 볼 수 있다.

### 2.2 API(Application Programming Interface)
- "다른 곳에 이미 있는 데이터 창고에, 정해진 방식으로 물어보면 답을 알려주는 창구."
- 예: 기상청에 "오늘 날씨 알려줘"라고 정해진 형식으로 물으면 기온·강수확률 데이터를 돌려준다.
- 직접 데이터를 조사하거나 손으로 입력할 필요 없이, 실시간으로 관리되는 진짜 데이터를 내 앱에
  그대로 가져와 보여줄 수 있다.
- 대표 예시: 기상청 단기예보, NEIS 급식정보, 에어코리아 미세먼지, NASA 오늘의 천문 사진(APOD),
  버스/지하철 도착정보 등.
- 대부분의 국내 공공데이터 API는 **공공데이터포털(data.go.kr)**에서 무료로 신청·발급받을 수 있다.

### 2.3 Google Sheets + Apps Script
- 학생이 제출한 데이터가 **쌓이고 저장되는** 앱을 만들려면 데이터 저장소(백엔드)가 필요하다.
- Google Sheets를 데이터 창고로, Apps Script를 그 데이터를 읽고 쓰는 서버 코드로 사용하면,
  별도 서버비 없이 이미 있는 구글 계정만으로 진짜 웹앱을 만들 수 있다.
- 배포 시 반드시 액세스 권한을 **"모든 사용자"**로 설정해야 하고, 이후 코드를 수정하면 "새 배포"가
  아니라 **"새 버전"**으로 재배포해야 기존 링크가 유지된다.
- 진짜 비밀로 지켜야 하는 API 인증키는 화면 코드(HTML)가 아니라 Apps Script(서버) 안에서만
  사용해야 안전하다.

### 2.4 바이브 코딩으로 쉽게 만들 수 있는 것 vs 아직 어려운 것

**✅ 쉽게 만들 수 있는 것**
- 정보를 모으고 보여주는 앱: 방명록, 신청서, 설문, 게시판, 출석부
- 정적인 정보 페이지: 소개 페이지, 발표자료 대신 쓰는 웹페이지
- 계산·변환 도구: 학점 계산기, 단위 변환기
- 퀴즈·미니게임
- 좋아요·댓글 같은 상호작용

**⚠️ 조금 어렵지만 도전할 만한 것**
- 이미지 업로드, 검색·정렬·필터, 관리자 전용 화면 같은 권한 나누기

**❌ 오늘 배우는 수준에서는 아직 어려운 것**
- 앱 안에 AI 기능 넣기(자동 요약, 챗봇 답변), 진짜 실시간 기능(웹소켓), 결제 기능,
  진짜 회원가입/로그인 시스템, 네이티브 앱, 대용량 데이터 처리

## 3. 실제 사례로 보는 바이브 코딩 (강사가 직접 만든 것들)

> 강의 도입부에서 신뢰도를 높이는 실제 사례로 활용. 모두 강사 본인이 무료 도구만으로 직접 제작·배포함.

### 3.1 수업에 바로 쓰는 도구
- **천구 좌표 시뮬레이터**: 방위각/고도, 적경/적위를 3D로 시각화하는 지구과학 수업용 시뮬레이터.
  Three.js 기반 3D 렌더링, 두 관측자 비교, 역방향 계산까지 지원. GitHub Pages로 배포.
- **단원평가 웹앱**: 선생님이 문제은행 스프레드시트를 복사해 방을 만들고, 학생은 6자리 방번호로
  입장해 단원평가를 푸는 웹앱. 객관식/주관식, 이미지 문제, 최고점수 기록 지원.

### 3.2 학교 행정 자동화
- **분실물 게시판**: 사진 첨부, 댓글, 좋아요, 기기 토큰 기반 본인 확인이 되는 인스타그램 감성 UI의
  학교 분실물 게시판.
- **고교 진학 희망 조사**: 로그인 없이 학번+이름으로 본인 확인 후 제출하는 설문 페이지, 관리자용
  통계·필터 대시보드 포함.
- **컴시간 크롤러**: 학교 시간표 시스템(컴시간알리미)에 공식 API가 없어, 웹페이지 동작을 그대로
  재현해 시간표 데이터를 가져오는 Apps Script 크롤러.

### 3.3 AI를 결합한 대규모 자동화 — 가장 임팩트가 큰 사례
- **과학교사 커뮤니티 자료 AI 자동 분류**: 다음카페에 수년간 쌓인 과학 수업자료 게시글 13,733건을
  전부 수집한 뒤, AI가 교육과정 단원(학교급/개정연도/과목/단원명)을 자동으로 태깅.
  - 사람이 수작업으로 하면 몇 달이 걸릴 분류 작업을 자동화.
  - 태깅 결과를 바탕으로 "단원별로 수업 둘러보기" 탐색 사이트를 구축.
  - 이후 뷰어들이 태그 오류를 제보하고 운영진이 검토·반영하는 관리 워크플로까지 확장.

### 3.4 재미·학급운영
- **초능력 윷놀이**: 실시간 온라인 멀티플레이가 되는 웹 윷놀이 게임. Firebase 실시간 데이터베이스로
  두 기기가 같은 방에서 애니메이션까지 실시간 동기화.

## 4. 오늘 실습 사이트 (padlet.html / gallery.html) 요약

두 페이지 모두 GitHub Pages로 배포된 정적 사이트이며, Firebase 실시간 데이터베이스를 이용해
로그인 없이 누구나 실시간으로 글을 올리고 볼 수 있다.

- 안내자료: https://ddelza.github.io/tt/padlet.html
- 작품 갤러리: https://ddelza.github.io/tt/gallery.html

### 4.1 padlet.html — 안내자료 + 질문/아이디어 게시판
4개 탭으로 구성되어 있으며, 각 탭에 그대로 복사해서 쓸 수 있는 예시 프롬프트가 담겨 있다.

- **🌱 초급 — 제미나이로 시뮬레이션 만들기**: 제미나이 Canvas 모드 켜는 법부터, 좋은 프롬프트를
  쓰는 4가지 요소(무엇을/누구를/어떻게 조작/무엇을 보여줄지), 과목별 예시 프롬프트 4개
  (옴의 법칙, 태양계 공전, 몰농도 계산기, 먹이사슬 시뮬레이션) 제공.
- **🔌 중급 — API로 실제 데이터 가져오기**: API 개념 설명과, 기상청 날씨·NASA 천문사진 API를
  실제로 연동하는 예시 프롬프트 제공. 인증키가 코드에 노출돼도 괜찮은 무료 API 위주로 실습.
- **🚀 고급 — Apps Script로 제출 페이지 만들고 배포하기**: 통째로 복사해서 AI에게 붙여넣으면
  AI가 단계별로 안내해주는 긴 지침서(메타프롬프트)를 제공. 스프레드시트 연결, Apps Script 배포,
  API 키를 서버에 안전하게 숨기는 심화 내용까지 포함.
- **📎 보조자료**: "바이브코딩으로 만들 수 있는 것 vs 어려운 것" 기대치 정리, 그리고 과학수업에
  바로 쓸 수 있는 공공 API 6종(NEIS 급식, 기상청, 에어코리아, 버스/지하철, NASA APOD, 재미용
  동물사진 API) 목록.
- 페이지 하단에는 실시간 질문·아이디어 게시판이 있어, 참가자가 막히는 부분이나 아이디어를 올리면
  전체 참가자에게 실시간(약 4초 간격)으로 공유된다.

### 4.2 gallery.html — 작품 제출 & 실시간 갤러리
- 제출 항목: 이름/팀명, 학교, 작품 제목, 한 줄 설명, **✨ 제미나이 공유 링크(필수)**,
  **🚀 Apps Script 웹앱 링크(고급 도전자만, 선택)**, 스크린샷(선택, 자동 압축).
- 레벨(초급/중급/고급) 구분 없이 하나의 통합된 갤러리에 모두 제출한다.
- 제출된 작품은 카드 형태의 갤러리 벽에 실시간으로 나타나며, 참가자끼리 서로 좋아요(♥)를 누를
  수 있고, 좋아요가 가장 많은 3개 작품은 상단에 "🏆 인기 TOP3"로 표시된다.
- 정렬 기준을 최신순/인기순으로 전환 가능.

## 5. 오늘의 진행 흐름 (60분, 실습 중심)

1. **도입 (5분)**: "학교 현장엔 딱 맞는 도구가 없다"는 공감대 형성, 오늘 무엇을 할지 소개.
2. **바이브 코딩 개념 + 실제 사례 (10분)**: 위 2장·3장 내용을 짧게 소개.
3. **실습 방법 안내 (5~10분)**: 팀 구성(초급/중급/고급), 사이트 사용법, 제출 방법 안내.
4. **실습 (30분 내외)**: 참가자들이 각자 원하는 레벨을 골라 직접 만들어보고, 막히면 질문 게시판 활용.
5. **작품 공유 & 마무리 (10분)**: 갤러리에 올라온 작품을 함께 둘러보고, 인기 작품 소개, Q&A.
