# PPT 슬라이드별 구성 계획

> NotebookLM에 `01-lecture-content.md`를 소스로 넣고, 이 문서를 "이 구조와 순서대로 슬라이드를
> 만들어줘"라는 지침으로 함께 제공한다. 총 60분 워크숍 중 실습(약 30분)을 제외한 강의 진행용
> 슬라이드로, 총 17장 분량이다.

---

## 디자인 원칙 (전체 공통 — 깔끔하고 심플하게)

- **슬라이드 1장 = 메시지 1개.** 여러 주장을 한 슬라이드에 욱여넣지 않는다.
- **텍스트는 최소한으로.** 한 슬라이드에 불릿 3~5개, 한 줄은 짧게. 문단 형태의 긴 설명 금지.
- **큰 글씨, 넉넉한 여백.** 뒤에서도 읽히도록 제목 32pt 이상, 본문 20pt 이상 권장.
- **색상은 2~3가지로 제한.** 메인 컬러 1개(보라/파랑 계열 — 실습 사이트와 톤 맞추기) + 강조색 1개
  + 무채색(회색/검정). 배경은 흰색 또는 아주 옅은 색.
- **이모지·아이콘은 포인트로만.** 섹션 구분이나 카드형 요약에 1~2개 정도, 남발하지 않는다.
- **코드/프롬프트 예시는 스크린샷이나 카드 박스로.** 긴 텍스트를 그대로 슬라이드에 붙이지 말고,
  실습 사이트 화면 캡처나 짧게 요약한 카드로 보여준다.
- **실습 안내 슬라이드는 큰 QR코드 + URL을 항상 고정 위치(우측 하단 등)에 배치**해서, 실습 중에도
  참가자가 언제든 확인할 수 있게 한다.

## 슬라이드 목록

### 1. 표지
- 제목: "AI에게 말로 시켜서 만드는 나만의 수업 도구"
- 부제: 바이브 코딩 워크숍 · 과학수업 연구회 · 2026-09-05
- 발표자명
- 디자인: 큰 제목 중앙, 배경은 심플한 그라디언트 또는 단색

### 2. 오늘의 목표
- 불릿 3개만: "① 바이브 코딩이 뭔지 이해한다 ② 직접 하나를 만들어본다 ③ 서로의 결과물을 공유한다"
- 디자인: 숫자 아이콘 3개 가로 배치

### 3. 문제 제기 — "학교엔 딱 맞는 도구가 없다"
- 기존 상용 앱은 복잡하거나 필요한 기능이 빠져 있음 / 외주는 비용·시간 부담
- 디자인: 좌우 대비 레이아웃 (기존 방식 vs 오늘 배울 방식)

### 4. 바이브 코딩이란?
- 한 문장 정의: "코드를 직접 짜지 않고, 원하는 걸 말로 설명하면 AI가 만들어주는 방식"
- 핵심 포인트 1개만 강조: "필요한 건 문법 지식이 아니라 구체적으로 설명하는 능력"
- 디자인: 정의를 큰 글씨로 중앙 배치, 화려한 장식 없이

### 5. 전통적 코딩 vs 바이브 코딩
- 소스 2.2절의 비교표를 단순화한 2열 비교 (진입장벽, 작업방식만)
- 디자인: 좌우 카드 2개

### 6. 실제 사례 — 수업에 바로 쓰는 도구
- 천구 좌표 시뮬레이터 / 단원평가 웹앱 (스크린샷 2장 + 한 줄 설명씩)
- 디자인: 스크린샷 중심, 텍스트는 캡션 수준으로만

### 7. 실제 사례 — 학교 행정 자동화
- 분실물 게시판 / 진학 희망 조사 (스크린샷 2장 + 한 줄 설명씩)
- 디자인: 6번과 동일한 레이아웃 반복 (일관성)

### 8. 실제 사례 — AI로 규모를 키운 자동화 (가장 임팩트 있는 사례)
- 과학교사 커뮤니티 자료 13,733건 AI 자동 분류
- 핵심 메시지 1개: "사람이 몇 달 걸릴 일을 AI가 자동화"
- 디자인: 큰 숫자(13,733)를 강조 비주얼로

### 9. 오늘 사용할 도구 3가지
- 제미나이 Canvas / API / Apps Script+Sheets — 아이콘 3개 가로 배치, 각각 한 줄 설명
- 디자인: 카드 3개 나란히 (뒤 슬라이드들과 색으로 연결)

### 10. 실습 구성 — 3단계 레벨
- 🌱 초급(시뮬레이션) → 🔌 중급(API) → 🚀 고급(Apps Script 배포)
- 각 레벨 옆에 "결과물"만 한 줄로 표기
- 디자인: 계단식/화살표로 난이도가 올라가는 느낌을 시각적으로 표현

### 11. 실습 사이트 안내
- "오늘의 모든 안내와 예시 프롬프트는 이 사이트에" — padlet.html 소개
- 큰 QR코드 + URL(ddelza.github.io/tt/padlet.html)
- 디자인: QR코드를 슬라이드 중앙에 크게, 실습 내내 다시 띄울 수 있도록 별도 슬라이드로 분리

### 12. 프롬프트 잘 쓰는 법
- 4가지 요소만: 무엇을 / 누구를 / 어떻게 조작할지 / 무엇을 보여줄지
- "마지막에 꼭 'html로 만들어줘' 붙이기" 강조
- 디자인: 4개 요소를 아이콘+단어로 심플하게 나열

### 13. 결과물 제출 안내
- gallery.html 소개: 제미나이 공유 링크 붙여넣기만 하면 끝
- 큰 QR코드 + URL(ddelza.github.io/tt/gallery.html)
- 디자인: 11번과 동일한 QR 레이아웃 (일관성, 참가자가 헷갈리지 않게)

### 14. 지금부터 실습! (타이머 슬라이드)
- 큰 텍스트: "30분간 자유롭게 만들어보세요"
- 막히면 질문 게시판(padlet.html 하단) 활용 안내
- 디자인: 타이머/시계 아이콘, 배경은 차분한 톤으로 실습 분위기 조성 (이 슬라이드를 실습 내내 띄워둠)

### 15. (실습 종료 후) 갤러리 함께 보기
- "우리가 30분 만에 만든 것들" — gallery.html 화면을 실시간으로 띄워서 발표
- 슬라이드 자체는 최소화: 제목 한 줄 + 화면 전환 안내만
- 디자인: 텍스트 거의 없이, 실제 화면 공유가 중심

### 16. 인기 작품 소개
- 갤러리 TOP3 작품을 발표 시점에 즉석으로 캡처해 넣거나, 발표 중 실시간 화면으로 대체
- 디자인: 🏆 1/2/3위 카드 레이아웃 (사전 제작 시 예시 이미지로 플레이스홀더 표시)

### 17. 마무리 & 다음 단계
