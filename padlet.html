🌱 초급 — 제미나이로 대화만으로 수업용 시뮬레이션 만들기

준비물: 구글 계정 (제미나이 무료 버전) 예상 소요: 30~40분 결과물: 제미나이 공유 링크

코드를 한 줄도 안 봐도 됩니다. "이런 걸 만들고 싶다"를 구체적으로 말로 설명하고, 나온 결과를 보면서 계속 다듬어가는 것이 전부예요.

  1. gemini.google.com에 구글 계정(학교 계정도 가능)으로 로그인합니다.
  2. 입력창 근처의 "도구"(＋) 버튼을 눌러 Canvas(캔버스) 모드를 켭니다. 캔버스 모드에서는 결과가 별도 화면에 코드/미리보기 형태로 나와서 수정하기 훨씬 편해요.
  3. (선택) 입력창 근처 모델 모드도 상황에 맞게 골라보세요 — 간단한 요청은 ⚡ 빠른 모드, 복잡한 요청은 🧠 사고 모드가 더 꼼꼼합니다.
  4. 프롬프트를 쓸 때 이 4가지를 포함하면 결과가 훨씬 좋아집니다: ① 무엇을(과학 개념) ② 누구를(대상 학년) ③ 어떻게 조작할지(슬라이더/버튼/입력값) ④ 무엇을 보여줄지(그래프/애니메이션/숫자) — 그리고 맨 끝에 반드시 "html로 만들어줘"를 붙이세요. 이 말이 있어야 브라우저에서 바로 열어볼 수 있는 완성된 코드로 나옵니다.
    중학교 2학년 대상으로 옴의 법칙(V=IR) 시뮬레이터를 만들어줘. 전압과 저항을 슬라이더로 조절하면 전류가 실시간으로 계산되고, 회로 애니메이션이랑 V-I 그래프도 같이 보였으면 좋겠어. html로 만들어줘.
    고등학교 지구과학 수업용으로 태양계 행성들의 공전을 3D로 보여주는 시뮬레이터를 만들어줘. 공전 속도를 조절할 수 있고, 각 행성을 클릭하면 이름과 거리 정보가 나왔으면 해. html로 만들어줘.
    중학교 3학년 화학 수업용 몰농도 계산기를 만들어줘. 용질의 질량과 몰질량, 용액의 부피를 입력하면 몰농도가 계산되고 단계별 풀이 과정도 같이 보여줘. html로 만들어줘.
    고등학교 생명과학 수업용 먹이사슬/개체수 변화 시뮬레이션을 만들어줘. 포식자와 피식자 초기 개체수를 입력하면 시간에 따른 개체수 변화 그래프가 애니메이션으로 그려졌으면 좋겠어. html로 만들어줘.
  5. 결과가 마음에 안 들면 코드를 고치려 하지 말고 "이 부분을 이렇게 바꿔줘"라고 계속 대화하세요. 캔버스는 대화를 이어가면서 같은 코드를 계속 고쳐나갈 수 있어요. 스크린샷을 그대로 보여주면서 "여기가 이상해"라고만 해도 충분합니다.
  6. 완성되면 화면 위쪽 공유 버튼으로 링크를 만들어 갤러리에 제출하세요. (다운로드 아이콘으로 .html 파일을 받아두면 나중에 다시 쓰기도 좋아요)
💡 팁 처음부터 완벽한 프롬프트를 쓰려 하지 마세요. 일단 대충 요청해서 나온 걸 보고 "이건 되네, 이건 이렇게 바꾸자"로 다듬는 게 더 빠릅니다.

🔌 중급 — API로 진짜 세상 데이터 가져오기

준비물: 구글 계정 (제미나이) 예상 소요: 30~40분 결과물: 실제 데이터를 보여주는 시뮬레이션

초급이 "내가 만든 화면 안에서만 동작하는" 도구였다면, 중급은 실시간으로 바뀌는 진짜 데이터(날씨, 급식, 천문 정보 등)를 가져와 보여줍니다. 이때 쓰는 창구가 API예요 — "정해진 방식으로 물어보면 답을 알려주는 곳"이라고 생각하면 됩니다. 내가 직접 만든 데이터만 쓸 수 있는 게 아니라, 이미 다른 기관이 실시간으로 관리하는 데이터를 그대로 "빌려와서" 보여줄 수 있어요.

  1. 먼저 보조자료 탭의 "바로 써먹는 API 모음"에서 쓰고 싶은 API를 하나 고릅니다. 오늘은 인증키가 필요 없거나, 무료로 즉시 발급되는 것 위주로 골라보세요.
  2. 인증키가 필요하다면 해당 사이트에서 "활용신청"/"인증키 신청" 메뉴로 무료 발급받습니다 (보통 즉시~1~2일 내).
  3. 제미나이 캔버스에서 아래 틀을 채워 요청합니다.
    [API 이름] API를 fetch로 불러와서 보여주는 html을 만들어줘. API 주소(엔드포인트)는 [API 문서 링크]이고, 필요한 인증키는 [발급받은 키]야. 가져온 데이터로 하고 싶은 것: [예: 오늘부터 3일간 우리 지역 날씨를 카드 형태로 보여줘] html로 만들어줘.
  4. 바로 써볼 수 있는 예시 두 가지:
    공공데이터포털의 기상청 단기예보 API를 fetch로 불러와서, 오늘부터 3일간 우리 지역 날씨(기온/강수확률)를 카드 형태로 보여주는 html을 만들어줘. API 주소는 [발급받은 엔드포인트], 인증키는 [발급받은 키]야. html로 만들어줘.
    NASA APOD API(https://api.nasa.gov/planetary/apod?api_key=DEMO_KEY)를 fetch로 불러와서, 오늘의 천문 사진과 설명을 보여주는 html을 만들어줘. 사진을 클릭하면 크게 볼 수 있었으면 좋겠어. html로 만들어줘.
  5. 완성되면 초급과 똑같이 공유 버튼으로 링크를 받아 갤러리에 제출하세요.
💡 팁 오늘 다루는 API들은 인증키가 코드에 그대로 보여도 큰 문제가 없는 무료·공개용 키예요. 로그인 정보처럼 진짜 안전하게 숨겨야 하는 값은 다음 단계(고급)에서 서버에 숨기는 법을 배웁니다.

🚀 고급 — Apps Script로 제출 페이지 만들고 배포하기

준비물: 구글 계정 + 제미나이 예상 소요: 40~50분 결과물: 데이터가 쌓이는, 배포된 웹앱

지금까지는 "혼자 쓰는" 도구였다면, 고급은 "학생들이 제출하면 데이터가 쌓이는" 진짜 웹앱입니다. 구글 스프레드시트를 데이터 저장소로, Apps Script를 서버로 씁니다 — 서버비 없이 이미 있는 구글 계정만으로 가능해요.

🤖 통째로 복사해서 AI에게 붙여넣기

아래 지침서를 통째로 복사해서 제미나이(또는 다른 AI 챗봇)에게 새 대화로 붙여넣고 전송하세요. 그다음부터는 AI가 한 단계씩 안내해줍니다. 스프레드시트 ID를 코드에 넣는 것처럼 손이 많이 가는 부분도 AI가 다 찾아서 채워줄 거예요.

📋 지침서 펼쳐서 복사하기 ▼
너는 지금부터 코딩을 전혀 모르는 선생님이 "구글 스프레드시트 + 구글 앱스크립트"로 데이터가 저장되는 웹앱(학생 제출 페이지, 신청서, 설문, 게시판 등)을 만드는 걸 도와주는 조수야. 아래 규칙을 반드시 지켜서 진행해줘. [진행 방식] 1. 먼저 나한테 "어떤 앱을 만들고 싶은지" 물어봐줘. (예: 학생 제출 페이지, 신청서, 익명 건의함 등) 내가 설명하면, 그 설명에 맞게 아래 기본 구조를 응용해서 코드를 짜줘. 2. 한 번에 모든 걸 쏟아내지 말고, 아래 [작업 순서]를 한 단계씩만 안내해줘. 내가 "완료했어" 또는 결과를 알려주면 그다음 단계로 넘어가줘. 3. "몇 번 메뉴의 몇 번째 버튼을 누르세요" 처럼 정말 구체적으로 알려줘. 나는 이런 걸 한 번도 안 해봤어. 4. 코드를 줄 때는 통째로 복사해서 붙여넣기만 하면 되도록 완성된 형태로 줘. 빈칸(예: SHEET_ID 자리)이 있으면 "이 부분에 무엇을 채워야 하는지" 정확히 알려주고, 내가 그 값을 알려주면 채워진 완성 코드를 다시 통째로 줘. [꼭 알아야 할 함정들 — 이것 때문에 다들 헤매니까 미리 챙겨줘] - 구글 앱스크립트 웹앱을 배포할 때 "액세스 권한"을 반드시 "모든 사용자"로 설정해야 해. "나만"으로 하면 나 말고 다른 사람은 못 써. - 화면(HTML)용 파일을 앱스크립트 안에 새로 만들 때, 파일 이름을 코드 속 createHtmlOutputFromFile('파일이름')에 적은 이름과 정확히 똑같이 맞춰야 해. (대소문자까지 똑같아야 함) - 화면 코드(HTML)의 <head> 안에는 꼭 <base target="_top"> 한 줄을 넣어야 해. 안 넣으면 앱스크립트 특유의 작은 화면(iframe) 안에 갇혀서 이상하게 보일 수 있어. - Code.gs나 HTML 코드를 고친 뒤에는, 저장만 해서는 반영이 안 돼. 반드시 "배포 → 배포 관리 → 연필 아이콘 → 버전: 새 버전 → 배포"를 다시 눌러야 실제 화면에 바뀐 내용이 나타나. (처음 배포할 때는 그냥 "새 배포"면 되지만, 한 번 배포한 뒤 코드를 고칠 때는 반드시 "새 버전"으로 해야 웹앱 주소가 안 바뀌어. "새 배포"를 다시 누르면 주소가 바뀌어버려서 이전에 공유한 링크가 깨져버려.) - 배포하고 나온 웹 앱 URL(링크)은 두 군데에 다 써야 해: (1) 화면 코드 안의 APP_URL 자리, (2) 사람들에게 공유할 접속 주소. 둘이 똑같은 주소야. [구글 스프레드시트 ID 찾는 법 — 나 대신 이렇게 안내해줘] 내가 스프레드시트 링크를 알려주면(예: https://docs.google.com/spreadsheets/d/1AbCdEfG.../edit), "/d/"와 "/edit" 사이에 있는 긴 문자열이 스프레드시트 ID라고 알려주고, 그 값을 코드의 SHEET_ID 자리에 직접 채워서 완성된 코드를 줘. 나더러 직접 잘라내라고 하지 말고, 네가 찾아서 채워줘. [기본 코드 구조 — 이 뼈대를 내 요청에 맞게 응용해서 짜줘] Code.gs: --- var SHEET_ID = "여기에_내_스프레드시트_ID"; function doGet(e) { var action = e.parameter.action; if (action === 'getList') { return ContentService.createTextOutput(JSON.stringify(getList())) .setMimeType(ContentService.MimeType.JSON); } return HtmlService.createHtmlOutputFromFile('Index').setTitle('내 앱'); } function doPost(e) { var data = JSON.parse(e.postData.contents); var result; if (data.action === 'addItem') { result = addItem(data); } else { result = { success: false, message: '모르는 요청입니다.' }; } return ContentService.createTextOutput(JSON.stringify(result)) .setMimeType(ContentService.MimeType.JSON); } function getSheet() { return SpreadsheetApp.openById(SHEET_ID).getSheets()[0]; } function getList() { var data = getSheet().getDataRange().getValues(); var list = []; for (var i = 1; i < data.length; i++) { list.push({ name: data[i][0], message: data[i][1] }); } return list.reverse(); } function addItem(data) { getSheet().appendRow([data.name, data.message, new Date()]); return { success: true }; } --- Index.html (앱스크립트 안에 "Index"라는 이름으로 새로 만드는 HTML 파일): --- <!DOCTYPE html> <html lang="ko"> <head> <base target="_top"> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1"> <title>내 앱</title> </head> <body> <h1>내 앱</h1> <input id="nameInput" placeholder="이름"> <input id="msgInput" placeholder="내용"> <button onclick="submitData()">등록하기</button> <ul id="list"></ul> <script> var APP_URL = "배포_후_받은_웹앱_URL_여기에"; function submitData() { var name = document.getElementById('nameInput').value; var msg = document.getElementById('msgInput').value; if (!name || !msg) { alert('모두 입력해주세요.'); return; } fetch(APP_URL, { method: 'POST', headers: { 'Content-Type': 'text/plain' }, body: JSON.stringify({ action: 'addItem', name: name, message: msg }) }) .then(function (r) { return r.json(); }) .then(function () { document.getElementById('nameInput').value = ''; document.getElementById('msgInput').value = ''; loadList(); }); } function loadList() { fetch(APP_URL + '?action=getList') .then(function (r) { return r.json(); }) .then(function (list) { var html = ''; list.forEach(function (item) { html += '<li><b>' + item.name + '</b>: ' + item.message + '</li>'; }); document.getElementById('list').innerHTML = html; }); } loadList(); </script> </body> </html> --- 이 뼈대를 내가 말한 앱 아이디어에 맞게 바꿔서(예: 항목 늘리기, 디자인 바꾸기, 좋아요 기능 추가하기 등) 완성된 코드로 다시 짜줘. 그리고 [진행 방식]에 따라 아래 순서대로 한 단계씩 나를 안내해줘: 1) 빈 구글 스프레드시트 만들고 링크 나한테 물어보기 2) 확장 프로그램 → Apps Script 들어가는 법 안내하고, Code.gs 코드 채워서 주기 3) HTML 파일("Index") 새로 만드는 법 안내하고, Index.html 코드 채워서 주기 4) 배포(웹 앱, 액세스: 모든 사용자) 방법 안내하고, 나온 URL을 Index.html의 APP_URL 자리에 다시 채워 넣도록 안내하기 (이때 최종 코드를 통째로 다시 줘) 5) 실제로 접속해서 테스트해보라고 안내하고, 안 되면 위 [꼭 알아야 할 함정들]을 하나씩 점검해주기 자, 이제 나한테 어떤 앱을 만들고 싶은지 물어보는 것부터 시작해줘.

전체 흐름 한눈에 보기

  1. 빈 구글 스프레드시트를 만들고 링크를 AI에게 알려줍니다. (AI가 스프레드시트 ID를 알아서 찾아냅니다)
  2. 스프레드시트 메뉴 [확장 프로그램 → Apps Script]로 들어가서, AI가 준 Code.gs 코드를 통째로 붙여넣고 저장합니다.
  3. 왼쪽 파일 목록 "＋" → HTML로 새 파일을 만들고(이름을 AI가 알려준 것과 정확히 똑같이), 화면 코드를 붙여넣습니다.
  4. 오른쪽 위 [배포 → 새 배포] → 유형: 웹 앱 → 액세스 권한: "모든 사용자"로 설정 후 배포. 나온 URL을 화면 코드의 정해진 자리(APP_URL)에 다시 채워 넣습니다.
  5. 배포된 URL로 직접 접속해서 제출해보고, 스프레드시트에 잘 쌓이는지 확인합니다.
💡 팁 코드를 다시 고쳤다면 반드시 [배포 → 배포 관리 → 연필 아이콘 → 버전: 새 버전]으로 업데이트하세요. "새 배포"를 다시 누르면 URL이 바뀌어서 이미 공유한 링크가 깨져버립니다.

🔐 더 나아가기 — API 키를 안전하게 숨기기

중급에서 다룬 API 중에는 인증키를 진짜로 숨겨야 하는 것도 있어요. 이번엔 Apps Script(서버)가 있으니, 화면 코드가 아니라 Code.gs 안에서만 API를 호출하도록 요청하면 키가 안전하게 숨겨집니다.

내 Apps Script 앱(Code.gs + 화면 파일)에 [API 이름] API를 연동하고 싶어. API 문서 주소는 [문서 링크]이고, 발급받은 인증키는 [발급받은 키]야. 이 API를 Code.gs 안에서 UrlFetchApp.fetch()로 호출해서 결과를 받은 다음, 화면이 fetch()로 불러갈 수 있게 새로운 action을 하나 추가해줘. 인증키는 절대로 화면(HTML) 코드에는 넣지 말고, Code.gs 안에서만 사용해야 해. 가져온 데이터로 화면에서 하고 싶은 것: [예: 오늘 날짜의 급식 메뉴를 목록으로 보여줘] 수정된 코드 전체를 다시 통째로 줘.

완성한 배포 URL은 갤러리 제출 시 "Apps Script 웹앱 링크"란에 추가로 남겨주세요.

📎 보조자료 — 팁 모음 & API 목록

오늘 다루는 범위를 넘어서 더 해보고 싶을 때, 또는 막혔을 때 참고할 자료입니다.

🧭 바이브코딩으로 만들 수 있는 것 vs 어려운 것

AI한테 "이거 만들어줘" 하면 뭐든 다 만들어줄 것 같지만, 쉬운 것과 어려운 것이 꽤 뚜렷하게 나뉩니다. 미리 감을 잡고 시작하면 훨씬 좋아요.

✅ 오늘 배운 수준으로 쉽게 만들 수 있는 것
  • 정보를 모으고 보여주는 앱 — 방명록, 익명 건의함, 설문/투표, 신청서, 게시판, 출석부/체크리스트
  • 정적인 정보 페이지 — 소개·포트폴리오 페이지, 발표자료 대신 쓰는 웹페이지
  • 계산·변환 도구 — 학점 계산기, BMI 계산기, 환율/단위 변환기
  • 퀴즈·미니게임 — 객관식 퀴즈, 반응속도 테스트, 클릭 게임
  • 좋아요·댓글 같은 상호작용 — 지금 이 갤러리에 쓰인 방식 그대로!
⚠️ 조금 어렵지만 도전해볼 만한 것
  • 이미지 업로드 — 사진 첨부 갤러리, 프로필 사진 등록
  • 검색·정렬·필터 — 이름으로 검색, 최신순/인기순 정렬
  • 권한을 나누는 기능 — 관리자 전용 화면 (오늘 만든 갤러리의 "삭제/수정" 정도는 충분히 도전 가능한 난이도예요)
❌ 오늘 배우는 수준에서는 아직 어려운 것
  • 앱 안에 AI 기능 넣기 (자동 요약, 챗봇처럼 대답하기) — 별도 유료 API와 보안 지식이 필요해요
  • 진짜 실시간 기능 (입력 중 표시, 화상채팅) — 웹소켓이라는 다른 기술이 필요합니다
  • 결제(돈 받기) 기능 — 정식 결제대행사와 계약이 필요한 영역
  • 진짜 회원가입/로그인 시스템 (비밀번호 설정·찾기) — 보안 지식이 많이 필요해요
  • 앱스토어에 올라가는 네이티브 앱, 무거운 사진/영상 편집·AI 그림 생성
  • 데이터가 수만 건 이상으로 아주 많아지는 경우 — 이땐 진짜 데이터베이스가 필요해요
